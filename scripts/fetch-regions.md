# 行政区划表的获取与更新

## 为什么要手动下载

两个原因，都不是懒：

1. **中国政府网站对境外网络不可达。** 实测 `mca.gov.cn` DNS 直接解析失败，
   `stats.gov.cn` 在 nginx 层返回 403。在国内网络打开则完全正常。
2. **一年才更新一次的数据，不值得维护定时任务和抓取失败告警。**
   而且页面改版会让定时任务默默失败，反而比手动更新更不可靠（docs/design.md §6）。

所以流程是：你下载，脚本解析。

## 数据源（在国内网络打开）

| 来源 | 地址 | 说明 |
|---|---|---|
| 民政部 | https://www.mca.gov.cn/n156/n186/ | 《中华人民共和国行政区划代码》，年度公布 |
| 国家统计局 | https://www.stats.gov.cn/sj/tjbz/tjyqhdmhcxhfdm/ | 统计用区划代码，前 6 位即行政区划代码 |

两者的 6 位代码是同一套（GB/T 2260），用哪个都行。
统计局的历年存档更齐，找往年数据更方便。

## 步骤

1. **下载当年及往前三年**的代码表，存成 `data/raw/<年份>.html`（或 .txt / .csv）。

   往前三年不是保险起见，是必须的——SC 证按**发证当时**的区划编码，
   只用最新表会查不到老证的产地，而那些产品完全合法。

2. 转换：

   ```bash
   node scripts/build-regions.js --source "国家统计局 统计用区划代码" --date 2026-08-27
   ```

   `--source` 要如实填。报告里会显示「查表依据：<来源> <日期>」，
   来源写错等于给家人看了一条假的证据链。

   脚本会检查省级代码数量（正常 31-34 个），明显不对会告警。

3. 生成导入文件并灌库：

   ```bash
   node scripts/seed.js
   ```

   产出 `dist/regions.jsonl`，在云开发控制台 → 数据库 → `regions` 集合 → 导入。
   多年度合并时新年份覆盖旧年份，**只在老年份出现的码会保留**——这正是覆盖历史区划的意义。

## 验收

拿几个家里现成包装上的 SC 号跑一遍，看产地能不能解出来。

解不出来**不是 bug**：按设计，查不到就显示「可能为历史区划，无法进一步核实」，
绝不判为非法（docs/design.md §6）。这一层只负责展示，不产出结论。
